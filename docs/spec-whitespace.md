# whitespace

## 概要

nospace とは、esolang である whitespace を改行、タブ・半角スペース等の空白無しで記述することを目標にした言語及びコンパイラです。

## 仕様

### コマンド (Commands)

#### IMP (Instruction Modification Parameters)

Whitespaceには異なるタイプのコマンドがあり、それぞれ異なるInstruction Modification Parameters (IMP、命令修飾パラメータ) を持ちます。IMPはコマンドが属するカテゴリと考えることができます。すべてのコマンドはIMPで始まり、その後にコマンドの残りの部分が続き、必要に応じてパラメータが続きます。

| IMP | コマンド |
|-----|---------|
| `[Tab][LF]` | I/O |
| `[Space]` | スタック操作 (Stack Manipulation) |
| `[Tab][Space]` | 算術演算 (Arithmetic) |
| `[LF]` | フロー制御 (Flow control) |
| `[Tab][Tab]` | ヒープアクセス (Heap access) |

#### 数値 (Numbers)

数値は符号(`[Space]`は正、`[Tab]`は負)で始まり、その後に2進数を表す`[Space]`(0)と`[Tab]`(1)のシーケンスが続き、`[LF]`で終わります。

### I/O

| コマンド | パラメータ | 意味 |
|---------|-----------|------|
| `[Tab][Space]` | - | スタックからヒープアドレスをポップし、ASCII文字を読み取り、そのヒープアドレスに文字を格納 |
| `[Tab][Tab]` | - | スタックからヒープアドレスをポップし、数値を読み取り、そのヒープアドレスに数値を格納 |
| `[Space][Space]` | - | スタックから数値をポップし、ASCII文字として出力 |
| `[Space][Tab]` | - | スタックから数値をポップし、数値として出力 |

IO命令の一般的なパターンは、最初の文字が入力の場合は`[Tab]`、出力の場合は`[Space]`です。2番目の文字は文字の場合は`[Space]`、数値の場合は`[Tab]`です。

### スタック操作 (Stack manipulation)

| コマンド | パラメータ | 意味 |
|---------|-----------|------|
| `[Space]` | Number | スタックに数値をプッシュ |
| `[LF][Space]` | - | スタックの最上位の項目を複製 |
| `[LF][Tab]` | - | スタックの最上位の2つの項目を交換 |
| `[LF][LF]` | - | スタックの最上位の項目を破棄 |
| `[Tab][Space]` | Number | スタックのn番目の項目(引数で指定)をスタックの最上位にコピー (v0.3) |
| `[Tab][LF]` | Number | スタックからn個の項目をスライドし、最上位の項目を保持 (v0.3) |

### 算術演算 (Arithmetic)

算術演算コマンドはスタックの最上位の2つの項目に対して演算を行い、演算結果でそれらを置き換えます。最初にプッシュされた要素が演算子の左側と見なされます。

| コマンド | パラメータ | 意味 |
|---------|-----------|------|
| `[Space][Space]` | - | 加算 |
| `[Space][Tab]` | - | 減算 |
| `[Space][LF]` | - | 乗算 |
| `[Tab][Space]` | - | 整数除算 |
| `[Tab][Tab]` | - | 剰余 |

### フロー制御 (Flow Control)

| コマンド | パラメータ | 意味 |
|---------|-----------|------|
| `[Space][Space]` | Label | プログラム内の位置にマークを付ける |
| `[Space][Tab]` | Label | サブルーチンを呼び出す |
| `[Space][LF]` | Label | ラベルに無条件にジャンプ |
| `[Tab][Space]` | Label | スタックの最上位がゼロの場合、ラベルにジャンプ |
| `[Tab][Tab]` | Label | スタックの最上位が負の場合、ラベルにジャンプ |
| `[Tab][LF]` | - | サブルーチンを終了し、呼び出し元に制御を戻す |
| `[LF][LF]` | - | プログラムを終了 |

ラベル (Label) は`[Space]`と`[Tab]`のシーケンスで、`[LF]`で終わります。

### ヒープアクセス (Heap Access)

ヒープアクセスコマンドは、スタックを参照して、格納または取得する項目のアドレスを見つけます。数値を格納するには、アドレスと値をその順序でプッシュし、その後storeコマンドを実行する必要があります。数値を取得するには、アドレスをプッシュし、その後retrieveコマンドを実行する必要があります。これにより、指定されたアドレスの値がスタックにプッシュされます。

| コマンド | パラメータ | 意味 |
|---------|-----------|------|
| `[Space]` | - | 格納 (Store) |
| `[Tab]` | - | 取得 (Retrieve) |

## 拡張仕様

`--std-ext` に引数を指定することで、以下の拡張機能を有効にできます。

### 負ヒープアドレスによる拡張 API

nospace20 の Whitespace インタプリタは、負のヒープアドレスを使用した拡張 API を提供します。

#### 使用方法

通常のヒープへの書き込み（Store 命令、または InputChar / InputNumber の格納）を使用しますが、アドレスとして負の値を指定します。
`--std-ext debug` が無効なときは、これらのアドレスへの書き込みは普通のヒープ書き込みであり、何もトリガーしません。

```
# __trace(42) の実装例
push -10     # トレース用アドレス
push 42      # トレースする値
store        # 格納（実際にはトレース記録）
```

#### API 仕様

| ヒープアドレス | 対応する nospace 関数 | `--std-ext` | 動作 |
|--------------|---------------------|------|------|
| `-10` | `__trace(n)` | `debug` | 値 `n` をトレース記録に追加。内部的に `traced[n] += 1` を実行（BTreeMap に記録） |
| `-11` | `__assert(n)` | `debug` | `n == 0` の場合、アサーション失敗エラーを発生させる。それ以外は何もしない |
| `-12` | `__assert_not(n)` | `debug` | `n != 0` の場合、アサーション失敗エラーを発生させる。それ以外は何もしない |
| `-13` | `__clog(n)` | `debug` | 値 `n` を `__clog: n` の行として clog 用の出力先に書く。`whitespace20` では stderr |

#### 詳細仕様

**トレース記録 (アドレス -10)**

- 値 `val` を書き込むと、`traced[val] += 1` が実行される
- `traced` は値の出現回数をカウントする BTreeMap
- 同じ値を複数回トレースすると、カウントが増加する
- 実行後、`traced` の内容を参照してテストや検証に使用できる

**アサーション (アドレス -11)**

- 値 `val` を書き込む
- `val == 0` の場合: `RuntimeError::AssertionFailed(val)` を発生させ、プログラムを停止
- `val != 0` の場合: 何もせず、次の命令に進む
- nospace の `__assert(condition)` に対応（条件が偽の場合に失敗）

**否定アサーション (アドレス -12)**

- 値 `val` を書き込む
- `val != 0` の場合: `RuntimeError::AssertionFailed(val)` を発生させ、プログラムを停止
- `val == 0` の場合: 何もせず、次の命令に進む
- nospace の `__assert_not(condition)` に対応（条件が真の場合に失敗）

**コンソールログ (アドレス -13)**

- 値 `val` を書き込むと、`__clog: {val}` と改行を clog 用の出力先に書く。ヒープには書き込まない
- 出力先はプログラムの標準出力とは別である。`whitespace20` では stderr。WASM（`WasmWhitespaceVM`）では出力を捨てる
- 出力順を保つため、書く前にプログラムの標準出力を flush する
- 出力先への書き込みエラーは無視し、実行を続ける
- nospace の `__clog(x)` に対応

#### Retrieve 命令の動作

負のヒープアドレスから Retrieve（読み取り）を実行した場合:
- 通常のヒープと同様に、初期化されていない場合は `0` を返す
- トレース記録や アサーション状態には影響しない

#### 標準 Whitespace との互換性

- 標準 Whitespace 実装では、負のヒープアドレスは通常のヒープの一部として扱われる
- nospace20 の拡張 API を使用したコードは、標準 Whitespace 実装では正しく動作しない可能性がある
- 互換性が必要な場合は、負のヒープアドレスを使用しないこと

#### エラーハンドリング

- アサーション失敗時は `RuntimeError::AssertionFailed(val)` が発生する
- CLI (`whitespace20`) では、エラーメッセージと共に終了コード 1 でプログラムが終了する
- トレース操作自体はエラーを発生させない

## メモリ上限

nospace20 の Whitespace インタプリタは、使用するメモリの量に上限を設けられます。Whitespace にコールスタックはないため、呼び出しの深さではなくメモリの量を制限します。無限再帰も、フレームや戻り先でメモリが伸びるため、この上限で止まります。

- 単位はセル（64 ビット整数 1 個）。使用セル数 = ヒープの書き込まれたことのあるアドレスの数 + データスタックの要素数 + 戻り先（Call で積まれたもの）の数
- 使用セル数を増やす操作（ヒープの新しいアドレスへの書き込み、Push / Duplicate / Copy、Call）で上限を超える場合、その操作を行わずに実行時エラー `memory limit exceeded: {上限} cells` で停止する。すでにオペランドを pop した命令（Store など）では、pop したオペランドは戻さない
- `whitespace20` では `--max-memory-cells <N>` で指定する。既定は `0`（無制限）
