# Whitespace 実行環境

nospace から whitespace へのコンパイルおよび whitespace コードの実行方式に関する設計ドキュメント。

## 背景

nospace の最終目標の1つは、nospace を whitespace へコンパイルし、whitespace インタプリタで実行できるようにすることである。

## 決定事項

### 実行方式: 2つのアプローチを併用

| アプローチ | 用途 | 配置場所 |
|-----------|------|----------|
| **whitespacers (外部 crate)** | 正式 whitespace 準拠テスト | `tools/` または `examples/` |
| **独自実装** | 通常のテスト・実行 | `src/whitespace/` |

### whitespacers (外部プロセス)

- **目的**: 正式な whitespace 言語対応の確認・テスト
- **利用方法**: バイナリには取り込まない。別途アプリケーションとしてビルドし、テスト時に外部プロセスとして実行
- **利点**:
  - ライセンス (MPL-2.0) の問題を軽減
  - 仕様準拠の保証
  - JIT による高速実行（必要な場合）

### 独自実装

- **目的**: 独自 API の組み込みサポート、テストバイナリとの連携
- **利点**:
  - `__trace()` 等の nospace 固有機能をフック可能
  - 外部プロセス呼び出しオーバーヘッドがない
  - テストコードは軽量なので JIT 不要
- **モジュール構造**:

```
src/
├── whitespace/
│   ├── mod.rs           # 公開API
│   ├── instruction.rs   # 命令定義 (enum WhitespaceOp)
│   ├── parser.rs        # バイトコード → 命令列パース
│   └── executor.rs      # 命令実行 (スタック、ヒープ、コールスタック)
├── compiler/
│   ├── mod.rs
│   └── grayspace/       # nospace AST → whitespace へのコード生成
```

## 独自 API の拡張方式

### 制約

- Tab/Space/LF 以外の文字は使用しない（whitespace の原則）
- 標準 whitespace インタプリタとの互換性を可能な限り維持
- 既存命令のプレフィックスとなるスロットは使用不可

### 拡張可能な命令スロット（完全版）

命令パース木を分析し、未使用かつプレフィックス衝突しないスロットを列挙する。

```
S = Space, T = Tab, L = LF, * = 任意の後続シーケンス

Root
├── [S] (スタック操作)
│   ├── [S] + Number       ← push (使用済)
│   ├── [T]
│   │   ├── [S] + Number   ← copy (使用済)
│   │   ├── [T]            ← 【拡張可能】
│   │   └── [L] + Number   ← slide (使用済)
│   └── [L]
│       ├── [S]            ← dup (使用済)
│       ├── [T]            ← swap (使用済)
│       └── [L]            ← pop (使用済)
│
├── [T][S] (算術演算)
│   ├── [S]
│   │   ├── [S]            ← add (使用済)
│   │   ├── [T]            ← sub (使用済)
│   │   └── [L]            ← mul (使用済)
│   ├── [T]
│   │   ├── [S]            ← div (使用済)
│   │   ├── [T]            ← mod (使用済)
│   │   └── [L]            ← 【拡張可能】
│   └── [L]                ← 【拡張可能】
│
├── [T][T] (ヒープアクセス)
│   ├── [S]                ← store (使用済)
│   ├── [T]                ← retrieve (使用済)
│   └── [L]                ← 【拡張可能】
│
├── [T][L] (I/O)
│   ├── [S]
│   │   ├── [S]            ← output char (使用済)
│   │   ├── [T]            ← output num (使用済)
│   │   └── [L]            ← 【拡張可能】
│   ├── [T]
│   │   ├── [S]            ← read char (使用済)
│   │   ├── [T]            ← read num (使用済)
│   │   └── [L]            ← 【拡張可能】
│   └── [L]                ← 【拡張可能】
│
└── [L] (フロー制御)
    ├── [S]
    │   ├── [S] + Label    ← mark (使用済)
    │   ├── [T] + Label    ← call (使用済)
    │   └── [L] + Label    ← jump (使用済)
    ├── [T]
    │   ├── [S] + Label    ← jz (使用済)
    │   ├── [T] + Label    ← jn (使用済)
    │   └── [L]            ← ret (使用済)
    └── [L]
        ├── [S]            ← ❌ プレフィックス衝突 ([L][L] = end)
        ├── [T]            ← ❌ プレフィックス衝突 ([L][L] = end)
        └── [L]            ← end (使用済)
```

#### 拡張可能スロット一覧

| # | スロット | カテゴリ |
|---|----------|----------|
| 1 | `[S][T][T]*` | スタック操作拡張 |
| 2 | `[T][S][T][L]*` | 算術演算拡張 |
| 3 | `[T][S][L]*` | 算術演算拡張 |
| 4 | `[T][T][L]*` | ヒープアクセス拡張 |
| 5 | `[T][L][S][L]*` | I/O 拡張 |
| 6 | `[T][L][T][L]*` | I/O 拡張 |
| 7 | `[T][L][L]*` | I/O 拡張 |

**注意**: フロー制御には拡張可能スロットなし（`[L][L]` が終端命令のため）

#### 実装時の検証

独自 whitespace インタプリタを実装する際は、標準命令セットの定義から拡張可能スロットをアルゴリズム的に列挙・検証するべきである。

```rust

    // 2. 各ノードで未使用の子を探索
    // 3. プレフィックス衝突（親が終端命令）をチェック
    // 4. 衝突しないスロットを返す
```

### 推奨方式: ヒープ経由の間接呼び出し

**特定のヒープアドレス（負数）への書き込みを拡張 API として解釈する方式を推奨。**

```
# __trace(42) の実装例
push -10        # 特殊アドレス（負数 = 拡張API呼び出し）
push 42         # トレース値
store           # ヒープ書き込み → 独自実装では __trace(42) として解釈
```

**利点**:
- 標準 whitespace インタプリタでも実行可能（拡張 API は無視されるだけ）
- whitespacers でのテストと独自実装でのテストで同じコードが使える
- プレフィックス衝突のリスクがない

### 拡張 API 一覧 (予定)

| アドレス | 機能 | 対応する nospace 関数 |
|---------|------|---------------------|
| `-10` | トレース出力 | `__trace(n)` |
| `-11` | アサーション | `__assert(n)` |
| `-12` | 否定アサーション | `__assert_not(n)` |
