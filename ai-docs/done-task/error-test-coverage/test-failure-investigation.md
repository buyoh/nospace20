# エラーテストケース失敗調査

## 概要

Phase 1-3 のエラーテストケース追加作業中、2件のテストが失敗しました。

## 失敗したテスト

### 1. test_syntax_error_missing_colon_let_001

**エラーメッセージ**:
```
Expected tree parse error but succeeded
```

**テストコード** (`missing_colon_let_001.ns`):
```nospace
# let 文のコロン欠落 #
func: main() {
  let x;
}
```

**実行結果**:
```
error: undefined variable: letx
```

**問題**:
- `let x;` という構文は、構文エラーにならない
- その結果、`letx` という変数が参照されているが未定義という意味解析エラーになる
- 構文解析段階ではエラーにならず、意味解析段階でエラーになる

**原因（空白無視の言語仕様による）**:
- **nospace言語は空白を無視する**ため、`let x;` は `letx;` と解釈される
- `letx` は1つの識別子（変数名）として認識される
- `let` がキーワードとして機能するには、後続にコロン `:` が必要
- このケースは構文エラーではなく、未定義変数の意味解析エラーとして正しく動作している

---

### 2. test_syntax_error_missing_comma_001

**エラーメッセージ**:
```
Expected tree parse error but succeeded
```

**テストコード** (`missing_comma_001.ns`):
```nospace
# 関数呼び出しのカンマ欠落 #
func: foo(a, b) {
  return: a;
}
func: main() {
  let: x;
  x = foo(1 2);
}
```

**実行結果**:
```
main exited
```

**問題**:
- `foo(1 2)` という構文が受け入れられ、正常に実行される
- カンマがなくても関数呼び出しとして解析される
- 引数が不足しているにも関わらず、エラーにならない

**原因（空白無視の言語仕様 + 引数チェック未実装）**:
- **nospace言語は空白を無視する**ため、`foo(1 2)` は `foo(12)` と解釈される
- `12` は整数リテラルとして認識され、1つの引数として関数に渡される
- `foo` 関数は2つの引数を期待しているが、1つしか渡されていない
- **引数の過不足チェックが実装されていない**ため、エラーにならずに実行される
- **本来は引数の数が一致しない場合、エラーとなるべき**

---

## 影響

全18件のテストケースのうち16件は正常に動作し、2件が失敗しています。

失敗した2件のテストケースは、nospace言語の「空白を無視する」仕様により、意図したエラーが発生しないケースです：

1. **missing_colon_let_001**: 言語仕様通りの動作（未定義変数エラーとして正しく検出）
2. **missing_comma_001**: 引数の過不足チェック機能が未実装のため、エラーにならない（**実装すべき機能**）

---

## 対応方針

### テストケース1（missing_colon_let_001）について

このテストケースは**構文エラーではなく意味解析エラー**として正しく動作しているため：
- 構文エラーテストとしては不適切
- 「未定義変数」のエラーテストとしては既に他のテストでカバーされている
- **削除またはコメントアウトが適切**

### テストケース2（missing_comma_001）について

このテストケースは**引数の過不足チェック機能の未実装**を示しているため：
- 将来、関数呼び出しの引数チェック機能を実装する際の重要なテストケース
- **テストファイルとして保持し、test-manifest.yaml ではコメントアウト**
- 引数チェック機能実装時に有効化すべき

### 選択した対応

**オプション B**: テストケースを保持し、将来の実装改善を待つ
1. テストケースのファイルはそのまま保持
2. test-manifest.yaml からこれらのテストをコメントアウト
3. ドキュメントに理由を記録

これにより、将来の実装改善時（特に引数チェック機能追加時）にすぐにテストを有効化できます。
