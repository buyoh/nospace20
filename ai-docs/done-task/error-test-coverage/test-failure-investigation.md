# エラーテストケース失敗調査

## 概要

Phase 1-3 のエラーテストケース追加作業中、2件のテストが失敗しました。

## 失敗したテスト

### 1. test_syntax_error_missing_colon_let_001

**エラーメッセージ**:
```
Expected tree parse error but succeeded
```

**テストコード** (`missing_colon_let_001.ns`):
```nospace
# let 文のコロン欠落 #
func: main() {
  let x;
}
```

**実行結果**:
```
error: undefined variable: letx
```

**問題**:
- `let x;` という構文は、構文エラーにならない
- `let` と `x` が別々のトークンとして解析され、セミコロンで文が終了
- その結果、`letx` という変数が参照されているが未定義というセミエラーになる
- 構文解析段階ではエラーにならず、意味解析段階でエラーになる

**原因**:
- Tree parser が `let` の後にコロンを必須としていない
- または、`let` がキーワードとして認識されていない可能性

---

### 2. test_syntax_error_missing_comma_001

**エラーメッセージ**:
```
Expected tree parse error but succeeded
```

**テストコード** (`missing_comma_001.ns`):
```nospace
# 関数呼び出しのカンマ欠落 #
func: foo(a, b) {
  return: a;
}
func: main() {
  let: x;
  x = foo(1 2);
}
```

**実行結果**:
```
main exited
```

**問題**:
- `foo(1 2)` という構文が受け入れられ、正常に実行される
- カンマがなくても関数呼び出しとして解析される
- おそらく `foo(1)` として解釈され、`2` は無視されるか、あるいは何らかの方法で処理されている

**原因**:
- Tree parser が関数呼び出しの引数リストでカンマを必須としていない
- または、"弱いエラー"として処理されているが、`parse_to_tree()` が `Err` を返していない

---

## 影響

全18件のテストケースのうち16件は正常に動作し、2件が失敗しています。

失敗した2件のテストケースは、現在の実装では構文エラーとして検出されないケースです。

---

## 対応方針

### オプション A: テストケースを削除

現在の実装では検出されないエラーなので、これらのテストケースを削除する。

### オプション B: テストケースを保持し、将来の実装改善を待つ

- テストケースはそのまま残す
- test-manifest.yaml からは削除する（またはコメントアウト）
- 将来、パーサが改良されたときに有効化する

### オプション C: 実装を修正してエラーを検出できるようにする

- Tree parser を修正して、これらのケースをエラーとして検出できるようにする
- より大きな変更になる可能性がある

---

## 推奨対応

**オプション B** を推奨します:
1. テストケースのファイルはそのまま保持
2. test-manifest.yaml からこれらのテストを削除
3. ドキュメントに将来の改善項目として記録

これにより、将来の実装改善時にすぐにテストを有効化できます。
