# Phase 5: ネスト関数のスコープ制御

## 目標

ネスト関数の可視性ルールを実装し、子スコープの関数が親からアクセスできないようにする。

## 言語仕様 (spec.md セクション 7)

```nospace
func: fn1() {
  let: x1;
  fn4();  # ok: 関数のホイスティング #
  func: fn2() {
    let: x2;
    # x1 = 1;  Bad: 親の関数スコープにアクセス不可 #
    x2 = 1;  # ok #
    func: fn2a() {
    }
  }
  func: fn4() {
    fn2();  # ok: 同一スコープの関数を呼び出し #
    # fn2a();  Bad: 子スコープの関数にアクセス不可 #
  }
  fn4();  # ok #
  x1 = 1;  # ok #
  # x2 = 1;  Bad: 子スコープの変数にアクセス不可 #
}
```

### ルール

1. **同一スコープの関数**: アクセス可能
2. **親スコープの関数**: アクセス可能
3. **子スコープの関数**: アクセス不可 ← **Phase 5 で実装**
4. **親の関数スコープの非 static 変数**: アクセス不可（Phase 3 で実装済み）
5. **親の関数スコープの static 変数**: アクセス可能（Phase 4 で実装済み）

## 現状

- ネスト関数の**定義**自体は動作する
- ネスト関数から親の関数スコープへのアクセス制御: Phase 3/4 で実装済み
- **未実装**: 子スコープの関数にアクセスできないようにする

## 必要な変更

### 1. semantic_analyzer: 関数の可視性スコープ

- 各関数がどのスコープで定義されたかを記録
- 関数呼び出し時に、呼び出し元のスコープから見えるかチェック

### 2. 関数解決ロジック

現在: `root_scope.get_function(name)` でグローバルに探索

変更案:
```rust
fn resolve_function(&self, name: &str) -> Option<FunctionRef> {
    // 現在のスコープから親スコープに向かって探索
    // 子スコープの関数は見えない
}
```

## 無効化されているテスト（Phase 5 で有効化予定）

Phase 4 実装時にネスト関数依存のため無効化されたテスト:

| テスト | 内容 |
|--------|------|
| `scope_nested_func_001` | ネスト関数の基本動作 |
| `scope_static_nested_001` | ネスト関数から static 変数アクセス |
| `scope_static_mixed_001` | static と非 static の混在（ネスト関数） |
| `scope_static_multi_decl_001` | 複数 static 変数宣言（ネスト関数） |
| `scope_static_counter_factory_001` | カウンターファクトリパターン |
| `scope_static_error_001` | 非 static 変数への関数境界越えアクセスエラー |

## 追加すべきテスト

- 子スコープの関数にアクセスしようとするとエラーになることを確認
- 同一スコープ、親スコープの関数にはアクセスできることを確認
