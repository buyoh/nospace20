# 未実装の型システム

このドキュメントは nospace プログラミング言語における未実装の型システムをまとめたものです。

最終更新日: 2026-02-07

## 概要

**状態**: ❌ 未実装

**説明**: 型システムは完全に未実装。現在は全ての値が整数として扱われる。将来的に以下の型を導入予定。

**参照**: [spec.md](../../spec.md) セクション A

---

## 計画中の型

### 1. int (整数型)

**説明**: 整数値を表す型。

**現状**: 現在、全ての値が暗黙的に整数として扱われている。

### 2. void (void型)

**説明**: 値なしを表す型。

**用途**: 
- 戻り値を返さない関数
- 式の評価結果が意味を持たない場合

### 3. function (関数型)

**説明**: 関数を値として扱うための型。

**用途**:
- 関数を引数として渡す
- 関数を戻り値として返す
- 高階関数のサポート

### 4. tuple (タプル型)

**説明**: 複数の値をまとめて扱う型。

**構文例**:
```nospace
let:point = (10, 20);  # 2要素のタプル #
let:x = point.0;       # 最初の要素 #
let:y = point.1;       # 2番目の要素 #
```

## 実装に必要な要素

### 1. 型定義

**場所**: 新規モジュール (例: `src/type_system/mod.rs`)

**必要な構造**:
```rust
pub enum Type {
    Int,
    Void,
    Function(Vec<Type>, Box<Type>), // (引数の型, 戻り値の型)
    Tuple(Vec<Type>),
}
```

### 2. 型チェック

**場所**: semantic_analyzer またはtype_checkerモジュール

**責務**:
- 式の型推論
- 型の整合性チェック
- エラー報告

**例**:
```nospace
let:x = 10;        # x: int #
let:y = "hello";   # エラー: 文字列型は未サポート #
x = y;             # エラー: 型が一致しない #
```

### 3. 型注釈 (オプション)

**構文例**:
```nospace
func: add(a: int, b: int) -> int {
  return: a + b;
}

let:x: int = 10;
```

**説明**: 型を明示的に指定する構文。型推論と組み合わせて使用。

### 4. 型エラーメッセージ

**例**:
```
error: type mismatch
  expected: int
  found: function
line:5 column:10
  x = foo;
      ^^^
```

## 実装のフェーズ案

### Phase 1: 基本型のサポート

**目標**: int と void 型を導入

**タスク**:
1. Type enum の定義
2. 式の型推論 (現状は全て int)
3. 関数の戻り値型のチェック

### Phase 2: 関数型のサポート

**目標**: 関数を値として扱う

**タスク**:
1. Function 型の定義
2. 関数を変数に代入
3. 関数を引数として渡す
4. 高階関数のサポート

### Phase 3: タプル型のサポート

**目標**: 複数の値をまとめて扱う

**タスク**:
1. Tuple 型の定義
2. タプルリテラルの構文
3. タプルの要素アクセス
4. パターンマッチング (オプション)

### Phase 4: ジェネリクス (将来)

**目標**: 型パラメータのサポート

**例**:
```nospace
func: identity<T>(x: T) -> T {
  return: x;
}
```

## 技術的課題

### 1. 型推論アルゴリズム

**選択肢**:
- 単純な型伝播 (簡単だが制限あり)
- Hindley-Milner 型推論 (強力だが複雑)

### 2. 型エラーの報告

**要件**:
- わかりやすいエラーメッセージ
- 位置情報の表示
- 型の期待値と実際の値の比較

### 3. 既存コードとの互換性

**課題**: 
- 現在の全ての値が整数として扱われる仕様からの移行
- 既存のテストケースの更新

---

## 優先度

**優先度**: 低 - 大規模な設計・実装が必要

**理由**:
- 型システムは言語全体に影響する大きな変更
- 慎重な設計と段階的な実装が必要
- 現時点では整数型のみで基本的な機能は実現可能
