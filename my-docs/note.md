## 記号の意図・雰囲気

異なる意図で使われることを防ぐ

- `:` : 特殊な構文の識別子
- `;` : 文の区切り
- `,` : 配列・タプルの区切り。構文の区切り
- `.` : 小数点
- `(`, `)` : 関数呼び出し、式のグルーピング。let の初期化表現
- `[` , `]` : 識別子の直後なら配列アクセス、それ以外なら配列リテラル（未実装）
- `{`, `}` : ブロックスコープ式
- `#` : コメント
- `@` : 型注釈（未実装）
- `$` : 未使用
- `~` : 未使用（ビット反転？）
- `` ` `` : 未使用
- `%`, `&`, `^`, `|` : 演算子

基本の雰囲気

```
# 制御構文 #
identifier: expr1, expr2 { block };
# 宣言 #
identifier: name1[num](expr1), name2[num](expr2);
# 関数定義 #
identifier: name0(name1, name2) { block }
```

if がかなり特殊な構文であることに気づいた。

```
if: cond {block} else: if: cond {block} else: {block};
```

問題点

- func だけ `;` が無い
- `{}` は式なので、`identifier: {0}, {0} {block};` のように書ける。カンマが無い。
- 構文としてのブロックをやめたほうが良いかもしれない。代わりに`,`を入れる。`identifier: expr1, expr2, { block };`
  - `{}` を省略できるようになる
    - `if` は出来ない。`if: cond, eval else: eval;` のように、evalとelseの区切りが曖昧になるため。
      - `;` で区切る？
        - `if` 全体で式なので、式の終了と勘違いする
  - `,` の個数で判断すると、関数呼び出し内でのコンマ曖昧性が発生
  - `func` はいまいちな感じになる。そもそも式の`{}`と`func`の`{}`を区別しなくても良いようにできるか？

## D 外部ファイルの読み込み

`include: "filename.ns";` のような構文で、外部ファイルを読み込む機能。

- 文体について `INCLUDE:` にするとか。`#` は使えないので `#include` はダメ
- いつ評価する？
  - C言語風: トークン解析の段階で、`include` 文を見つけたら、指定されたファイルを読み込んで、その内容を現在のファイルの内容に挿入する。
  - モジュール: `include` 文を見つけたら、指定されたファイルをモジュールとして読み込む？
  - インクルードガードあり
- スコープは？
  - 案1: 同一スコープであり、直前に読み込まれたり既に定義された識別子の影響を受ける。C言語。
  - 案2: モジュールとして独立したスコープを持つ。外部から参照できるようにするには、`func: export: a(){}` のように export が必要。export された識別子を参照するには `include: "filename.ns", namespace;` のように名前空間を指定して、`namespace.a()` のようにアクセスする。
- include によってファイルが読み込まれたとき、そのファイルに`__main()`を含む場合は、そのタイミングでそのファイルの`__main()`が実行される。

wasm / javascript 対応の考慮も必要。

## E 一時配列

`puts("Hello")` や、`print([1, 2, 3])` のように、配列を直接記述したい。

候補1: ライフタイムはスタック同様その文の評価中のみ。評価が終わったら破棄される。

- 例えば、`puts("Hello") + 3;` と書いた場合、`"Hello"` は一時配列として確保され、`puts` に渡される。`puts("Hello") + 3;` の評価が終わったら、`"Hello"` は破棄される。
  - 式ではない。式の場合、`"Hello"` が解釈された直後に破棄するので。
- C++ の右辺値 `std::vector` と同じ。

候補2: これは無名 static (const) 変数である。

- エントリーポイントが呼び出される前に、これらの配列はstaticな変数同様メモリ上に確保される。
- これらは const であるべきだが、未実装のため、書き換えられてしまう。
- 関数呼び出しで書き換えられると、以降の呼び出しでも書き換わった値が渡される
- C や Java の文字列と同じ。
